# Claude re-audit package (portable)

Independent re-audit of Gemini's v4–v6 momentum audits. The verdict is in [CLAUDE_REAUDIT_REPORT.md](CLAUDE_REAUDIT_REPORT.md).

## Reproduce

```bash
git clone https://github.com/nickchen494949/macro-observer && cd macro-observer
# 1) supply the raw data (NOT in git, see below)
# 2) run
bash outputs/claude_reaudit_20261102/run_all.sh          # ~5 min, writes results/
```

- Paths are relative. Everything resolves from this folder, or from `MACRO_REPO_ROOT` if set (see `_paths.py`).
- Intermediate files (`_work/*.parquet`, `_work/*.pkl`) are regenerated by the scripts and are gitignored.
- Small result tables (`results/*.csv`) **are** committed, so a reader can check numbers without rerunning.

## Raw data is NOT on GitHub

`research/sector_stock_momentum/.gitignore` excludes `data/raw/`, `data/raw_open/`, `data/raw_tiingo/`, `data/raw_wiki/`, `data/raw_archive/` and several others. Those folders hold about 1,500 vendor files (Yahoo, Tiingo, Nasdaq WIKI). They come from the project's own fetchers (`fetch_prices.py`, `fetch_tiingo.py`, `fetch_wiki.py`) and are not redistributed.

[`INPUT_MANIFEST.csv`](INPUT_MANIFEST.csv) lists the **SHA-256 of every input file** the independent scripts read, and whether each one is in git. A third party who re-fetches the data can verify byte-identity. A file whose hash differs (for example, a vendor revision) will cause small numeric differences.

## What each script is, and how independent it is

| Script | Independent of Gemini code? | Purpose |
|---|---|---|
| `01_indep_rebuild.py` | ✅ yes (reads raw JSON only) | Naive PIT panel: 12-1/6-1/3-1, RS windows, SMA200, next-open returns |
| `claude_engine.py` | ✅ yes | Portfolio simulator (Top-K, RS/SMA gates, drifted weights, 10bp). Risk-free rate (rf) from **raw FRED** |
| `02_compare_vs_gemini.py` | ✅ yes; Gemini ledgers are only the *comparison target* | Month-by-month pick and return comparison |
| `03_mismatch_diagnosis.py` | ✅ yes | Classifies **every** mismatch month from raw files (0 unexplained) |
| `04_ledger_math_and_big_months.py` | ✅ yes | Recomputes headline CAGR/MDD from ledgers; checks the 15 largest months against raw opens |
| `05_open_fallback_status.py` | ⚠️ Part A uses Gemini's engine **by design** (audits what *their* code did); Part B is independent | How often "next-day open" really used a close price |
| `06_family_multiple_testing.py` | ⚠️ runs on **both** engines: `claude` (independent) and `gemini` (audited) | Formal multiple testing over 60 hypotheses: bootstrap p, Bonferroni, Holm, White Reality Check, Hansen SPA_c |
| `07_spy_excess_regime.py` | uses 06 series from both engines | Momentum vs SPY, excluding the best months, 2010–22 vs 2023–26 |
| `08_nov2026_signal.py` | ✅ yes | November signal recomputed with dated, sourced prices |
| `09_input_manifest.py` | ✅ yes | SHA-256 manifest |

## Known limitations

- The independent rebuild does **no ticker-alias stitching**, so it cannot hold renamed or reused tickers (COG, HFC, FB, EA…). Script 03 shows that every resulting mismatch is of that type.
- The 2026-10-30 closes are external (Yahoo spark quote; stockanalysis.com for SPY), because the raw files end on 10-27 (closes) and 10-29 (opens). Their sources are documented in script 08.
- The multiple-testing family has 60 hypotheses. The project's real search space was larger (tech universe, XLK and sector benchmarks, close vs open, two windows), so the family-wise p-values are **optimistic**.
